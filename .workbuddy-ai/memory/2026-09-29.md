# 2026-09-29

## Refactor struktur proyek ADMS (main.py + db.py)

**Masalah pada kode awal:**
- `main.py`: `HTTPException` dipakai tapi tidak diimpor → `GET /items/{id}`
  sebenarnya crash 500 saat item tidak ada. Diverifikasi: import lama akan
  melempar `NameError`.
- `db.py`: `load_dotenv()` mengeksekusi `os.getenv()` di level modul, jadi
  kredensial "beku" saat impor dan tidak bisa di-override runtime.
- Tidak ada validasi kredensial; gagal jauh di dalam kueri.
- Koneksi baru dibuka tiap panggilan `connect()`, tanpa pool dan tanpa jaminan
  penutupan.
- `requirements.txt` memakai `mysql.connector` — bukan nama PyPI valid
  (yang benar `mysql-connector-python`).
- Tidak ada test, tidak ada model respons, tidak ada pemisahan lapisan.

**Struktur baru:**
```
main.py              -> tipis, hanya create_app()
app/application.py   -> application factory
app/config.py        -> settings dataclass + get_settings() (lru_cache) + fail-fast
app/database.py      -> MySQLConnectionPool (lazy) + context manager connection()
app/schemas.py       -> model Pydantic respons
app/store.py         -> data in-memory, rute tidak menyentuh struktur data
app/routers/health.py, items.py
tests/               -> 9 test
db.py                -> shim kompatibilitas mundur untuk db.connect()
```

**Keputusan desain yang perlu diingat:**
- Pool MySQL dibuat **malas**: `_get_pool()` baru jalan saat koneksi pertama
  diminta. Ini disengaja supaya `import app.database` tidak menyentuh jaringan
  dan test bisa jalan tanpa MySQL.
- `contextlib.connection()` selalu menutup koneksi di `finally` — perbaikan
  penting, karena kode lama membocorkan koneksi.
- `/health` selalu balas 200 walau DB mati; statusnya dibedakan lewat field
  `database: ok|degraded`, supaya probe tidak menganggap app mati.
- `DEBUG=true` yang membuka `/docs`; di produksi default tertutup.
- Rute item dinaikkan dari `/{item_id}` ke prefix `/items` agar tidak menelan
  seluruh path root (`/health` dulu akan tertangkap sebagai `item_id`).
  **Ini perubahan bentuk URL yang perlu diperhatikan** — `/items/foo` tetap
  sama, tapi `GET /` dan `/health` kini terpisah dengan benar.

**Cara verifikasi yang dipakai (terbukti jalan):**
- `pytest -v` → 9 passed, tanpa butuh MySQL.
- Boot asli `uvicorn main:app --port 8077` lalu curl: `/`, `/items/foo`,
  `/items/nope` (404 dengan pesan Indonesia), `/health` (degraded), dan
  `/openapi.json` (200).
- Konfigurasi kosong diuji terpisah → `ConfigError` dengan pesan yang jelas.
